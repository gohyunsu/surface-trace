# 대면 미팅 피드백에 답하는 시연 영상

대면 미팅에서 **이미 받은 실무자 의견**을 발표에서 답하기 쉬운 네 질문으로 재구성했다. 이는 기업에 다시 보낼 평가 문항이나 실무자의 직접 인용이 아니다. 회의록에 함께 적힌 **팀의 개발 제안**과 실무자 의견도 구분한다. 영상에서는 질문마다 구현 화면과 검증 결과로 답하고, 아직 해결하지 못한 요구도 구분한다. 흐름은 `미팅 피드백 → 개발 방향 → 데이터·방법 선택 이유 → 실제 동작 → 검증 결과와 한계`다.

## 이전 피드백을 재구성한 네 질문과 현재의 답

| 항목 | 기존 미팅 의견을 질문으로 재구성 | 영상에서 제시할 답과 근거 |
| --- | --- | --- |
| ① 구현·시연 수준 | **“이상 영역과 점수만 보여주는 시제품이 생산라인의 빠른 판정 요구에 답하는가?”** 실무자는 사람이 사진을 매번 읽는 방식과 이상 영역 표시만으로는 라인 적용이 어렵다고 했다. | 초기 KolektorSDD 한 장 검사에서 연속 사진의 이상 위치·변화 경보·구간 요약·소수 검수·기준 갱신 판단으로 범위를 넓혔다. 초기 MVP는 브라우저에서 새 사진을 추론하지만, 개선 버전은 서버에서 계산한 TSFabrics 결과의 웹 재생이다. **자동 합격·불합격 판정과 결함 유형·크기 분류는 구현하지 않았다.** 따라서 생산라인 판정 요구에는 부분적으로만 답한다. |
| ② 사용 데이터의 적절성 | **“정돈된 공개 사진을 넘어, 시간에 따라 외관이 달라지는 생산 사진에서도 시험했는가?”** 실제 고무 제품은 질감·명암·촬영 각도와 라인 흔들림의 영향을 받는다는 의견이었다. | TSFabrics의 시간순 편직 생산 사진 93,196장·22개 구간으로 연속 이미지의 외관 차이와 검수 흐름을 시험했다. 공개 결함 라벨은 검수 대상 선정에 사용하지 않고 사후 평가와 요청된 사진의 확인 결과 재생에 사용했다. 고무벨트·라인스캔·현장 흔들림에서의 성능은 아직 검증하지 못했다. |
| ③ 방법론의 타당성 | **“불량 사례가 적고 공정 변경이 AI팀에 늦게 공유될 때, 변화를 발견하고 확인할 사례를 고르며 현장 판단을 반영할 수 있는가?”** 미팅에서는 새로운 결함과 현장·개발자의 판단 차이도 지적했다. | 고정 DINOv2 특징으로 이상 점수·위치를 구하고, 별도 MMD 신호로 외관 변화를 감지한다. 점수가 높은 사진을 시간상 분산해 2건부터 확인하고 필요하면 최대 8건을 요청한다. 검수된 정상 사진으로 만든 갱신 후보는 후속 데이터에서 결함 탐지가 줄어 **적용 보류**했다. 확인 결과 기록과 갱신 후보 평가는 가능하지만, 검수 라벨로 탐지 성능을 높였다고 말할 수 없다. 공정 변경의 원인 판별과 결함 유형 자동 라벨도 구현하지 않았다. |
| ④ 실무 활용 가능성 | **“사진마다 알림과 추가 입력을 요구하지 않고, 담당자가 기간별 핵심 결과를 확인할 수 있는가?”** 실무자는 구간 요약을 제안했고 처리 속도, 현장 PC, 망 제약도 함께 제기했다. | 구간 요약에 처리 장수·점수 추이·변화 신호·확인할 사진을 묶는다. 최종 16개 구간의 재생 평가에서 고정 8건 요청 128건이 2건 우선 규칙으로 56건이 됐고, 발견한 신규 결함 사건은 양쪽 모두 26/90건이었다. RTX 3090에서 축소 사진을 8장씩 처리한 속도는 105.48장/초였지만, 실제 현장 PC·원본 해상도·오프라인 운영과 MES/PLC 연동은 시험하지 않았다. |

### 답의 경계

- 초기 MVP의 KolektorSDD 수치와 개선 버전의 TSFabrics 수치를 직접 비교하지 않는다. 수작업 특징과 DINOv2는 **같은 TSFabrics 사진의 방법 비교**로, 기준 사진 선택과 검수 간격은 **동일 예산의 2×2 요인 비교**로 제시한다.
- 변화 시험은 서로 다른 실제 녹화 구간을 **알려진 경계에서 연결**한 것이다. 미지의 실제 공정 변경 시점이나 변경 원인을 알아낸 결과로 말하지 않는다.
- 새 기준 후보는 검수 결과를 반영해 시험했으나 채택하지 않았다. 결함 유형 자동 라벨링, 현장 판단으로 재학습한 모델의 성능 향상, 설비 연동은 발표 구성안의 방향 중 **미구현 범위**다.
- 사이트의 개선 버전은 저장된 실제 사진과 모델 출력의 재생이다. 영상에서 이를 온라인 현장 추론처럼 연출하지 않는다. 요청된 사진의 공개 라벨은 검수 장면 전까지 숨긴다.
- 회의록의 자동 라벨링 초안·결함 유형 분류·확인 라벨을 이용한 재학습은 **팀이 제안한 개발 방향**이다. 실무자의 직접 요구나 현재 완성된 기능으로 소개하지 않는다. 실무자의 의견은 촬영 변동, 드문 불량, 판정 불일치, 공정 변경 전달 지연, 빠른 판정, 개별 알림·입력 부담, 인프라 제약이다.

## 영상 구성 · 한국어 내레이션 · 약 4분 35초

**형식:** 1920×1080 화면 캡처와 한국어 음성. 영어 사이트는 그대로 촬영하고, 화면의 핵심 용어만 짧은 한국어 자막으로 보조한다. 첫 장면에 네 질문을 길게 열거하지 말고, 장면이 전환될 때 관련 질문 한 줄을 잠깐 표시한다. 담당자에게 점수·보완 의견을 새로 요청하는 장면은 넣지 않는다. 마지막은 **기존 피드백에 대한 현재 답과 미해결 범위**로 마무리한다.

### 선택 컷 · 같은 검수 예산의 재배분

검수 부담에 대한 답을 더 보여줄 시간이 있다면, `Start with two checks` 아래의 검수 예산 그래프를 15초간 삽입한다. **고정 배분 128건·발견 26건 → 조용한 구간에서 일찍 멈춤 56건·발견 26건 → 남은 예산 재배분 128건·발견 50건**을 같은 눈금에 차례로 보여준다. 재배분 시 조용한 12개 구간에는 첫 두 장에 독립 감사 확인 1건씩을 더하고, 나머지 검수를 문제가 확인된 구간으로 옮긴다. **추가 24건은 모두 한 구간에서 나왔다.** 이 배분 규칙은 초기 결과를 본 뒤 설계한 탐색 비교이므로 본편의 확정 성능 개선 수치와 합치지 않는다. 내레이션은 “먼저 두 장을 확인하면 검수 시간을 줄일 수 있습니다. 같은 예산을 다시 쓰는 방법도 시험했지만, 추가 발견은 한 긴 구간에 집중됐습니다.” 정도로 제한한다. 모델의 이상 점수나 기준이 학습으로 개선된 장면처럼 연출하지 않는다.

### 화면 연출 · 촬영 체크리스트

1. **피드백 → 방향:** 회의 일러스트 아래 네 쟁점을 한 번에 띄우지 않고 차례로 밝힌다. 마지막 문구가 남아 있을 때 초기 한 장 검사 화면으로 컷 전환한다. 같은 위치에 `한 장 → 연속 구간`을 짧게 겹쳐 보여주면 문제 정의의 변화를 알 수 있다.
2. **데이터:** KolektorSDD는 사진 한 장, TSFabrics는 실제 시간순 사진 4~5장을 같은 높이로 놓는다. 사진들이 오른쪽으로 이어지는 움직임을 사용해 “시간 순서”가 데이터 선택의 이유임을 그림으로 보여준다. 두 데이터셋의 성능 수치를 이 화면에서 나란히 놓지 않는다.
3. **이상 위치 → 변화:** 동일 사진의 두 히트맵을 화면 좌우에 고정하고 가운데 경계만 이동시켜 위치 차이를 보여준다. 이어 기준 구간과 새 구간 사진을 같은 자리에 교체하고 변화 점수 선을 그려, 개별 결함과 전체 외관 변화가 별도 신호임을 드러낸다.
4. **검수:** 점수 그래프의 여덟 점과 사진 여덟 장을 같은 색으로 연결한다. 처음 두 장만 밝게 보이고, 확인 결과가 나타난 뒤 나머지 여섯 장이 열리게 한다. 두 장이 모두 정상인 경우의 `Review six more` 버튼은 짧은 별도 컷으로 제시한다. 영상의 실제 사례에서는 첫 두 장이 결함이므로 자동으로 여섯 장이 열린다.
5. **갱신 판단:** 정상 사진 경보 막대가 줄어드는 장면에서 바로 성공 표시를 하지 않는다. 곧이어 결함 사진 경보와 발견 사건 막대도 줄어드는 장면을 보여주고 `Keep frozen`에서 멈춘다. 이때 범위 표기 `별도 15개 구간 평가`를 유지한다.
6. **검증과 마무리:** 수치는 `방법 비교 → 변화 신호 → 검수 효과 → 갱신 보류` 순서로 한 카드씩 교체한다. 각 카드에 분모와 평가 구간 수를 남긴다. 마지막 두 줄은 검증한 범위와 아직 시험하지 않은 현장 조건만 표시한다.

## 편집 시 지킬 구분

1. **시연 사례와 집계 결과를 구분한다.** 히트맵은 선별한 예시, 변화·검수는 한 녹화 구간, 갱신 보류는 별도 15개 구간 평가다. 장면 상단에 각각 `예시 사진`, `한 녹화 구간`, `15개 구간 후속 평가`처럼 범위를 표시한다.
2. **수치의 분모를 남긴다.** DINOv2 평균 AP는 결함 포함 4개 구간, 15/16은 알려진 녹화 구간 전환, 26/90은 같은 구간당 8건 검수에서 찾은 신규 결함 사건이다. 2×2 표는 동일한 최종 조합으로 향하는 비교이므로 두 개선량을 합산하지 않는다.
3. **구현과 계획을 분리한다.** 구간 요약·검수 결과 기록·후보 평가와 보류는 보여줄 수 있다. 결함 유형 분류, 새 라벨로 재학습해 성능 향상, 현장 PC에서 100장/초 처리, MES/PLC 연결은 시연 결과처럼 넣지 않는다. 3090 배치 처리량은 [별도 서버 속도 측정](../experiments/unsupervised/THROUGHPUT_RESULTS.md)으로만 제시한다.
