# SurfaceTrace | 현장 피드백을 반영한 최종 구현 파이프라인

SurfaceTrace는 생산 이미지에서 눈에 띄는 영역을 찾고, **외관 변화와 검수 결과를 일정 구간 단위로 정리해 현장과 AI 개발팀이 같은 사례를 보며 판단하도록 돕는** 프로토타입이다. 초기 버전은 단일 사진의 이상 영역 표시를 검증했다. 개선 버전은 시간 순서가 있는 생산 이미지를 대상으로 변화 신호, 제한된 검수 요청, 기준 갱신 후보의 검증까지 다룬다.

## 1. 어떤 피드백을 반영했나

| 대면 미팅에서 확인한 문제 | 기존 프로토타입 | 개선한 방향 |
| --- | --- | --- |
| 불량 사진과 확정 라벨을 충분히 확보하기 어렵다 | 정상 패치와의 수작업 특징 거리로 단일 사진을 검사 | 사전학습된 **DINOv2**의 패치 특징으로 라벨 없이 이상 점수와 위치를 산출 |
| 재료·공정 조건이 바뀌어도 AI팀에 즉시 공유되지 않을 수 있다 | 사진별 이상 점수만 표시 | 결함 점수와 별도로 **연속 이미지의 전체 외관 변화**를 감지 |
| 모든 결과를 개별 알림으로 보내면 현장의 확인 부담이 크다 | 사진 한 장의 결과를 열어 확인 | **구간 요약**과 시간상 떨어진 소수의 검수 사진을 제시 |
| 현장 판단과 모델 판단이 다르고, 정상 기준을 잘못 갱신하면 결함을 놓칠 수 있다 | 검수 결과를 모델 개선과 연결하지 않음 | 확인 결과를 기록하되, 새 기준은 **별도 후보로 평가**하고 결함 탐지가 나빠지면 기존 기준 유지 |

회의에서 언급된 촬영 흔들림·조명 변화, 처리 속도, 오프라인 환경은 실제 도입 시 중요한 요구다. 현재 구현은 공개 생산 이미지로 위의 **검사·소통 절차**를 검증한 단계이며, 동일고무벨트의 카메라·설비 연동이나 고무 제품 성능은 아직 시험하지 않았다.

## 2. 기존 버전과 개선 버전의 차이

| 항목 | 초기 MVP | 피드백 반영 버전 |
| --- | --- | --- |
| 데이터 | KolektorSDD: 전기 정류자의 플라스틱 매립부 균열 사진 | TSFabrics: 22개 생산 시나리오의 시간 순서가 있는 편직 라인 사진 93,196장 |
| 특징·점수 | 밝기·경계 등 8개 수작업 패치 특징을 정상 패치와 비교 | 고정된 DINOv2-S/14 패치 특징을 정상 기준과 비교 |
| 입력·출력 | 한 장의 사진 → 이미지 점수·히트맵 | 연속 사진 → 점수 추이·히트맵·외관 변화 신호·구간 요약 |
| 검수 | 사용자가 샘플을 직접 열어 확인 | 점수가 높은 사진을 시간상 분산해 선정하고, 우선 2건 확인 후 추가 요청 여부 결정 |
| 기준 갱신 | 없음 | 후보 기준을 별도로 시험하고, 후속 구간에서 결함 탐지가 떨어지면 적용 보류 |
| 사이트 동작 | 보관된 샘플 64장에 브라우저에서 실제 추론 | 서버에서 계산한 TSFabrics 결과와 현장 확인 절차를 녹화된 실행처럼 재생 |

두 버전은 **데이터셋과 평가 방식이 다르므로 성능 수치를 직접 대결시킨 결과가 아니다.** 개선 효과는 아래처럼 같은 TSFabrics 조건 안에서 요소별 비교로 확인했다.

## 3. 현재 파이프라인

**시간 순서의 이미지 → DINOv2 이상 점수·위치 표시 + 별도 외관 변화 감지 → 구간 요약·검수 요청 → 담당자 확인 → 새 기준 후보의 후속 평가 → 유지 또는 보류**

### 이미지 점수와 이상 위치

- 한 생산 구간의 이미지 크기·색상 정규화 절차를 고정한다. TSFabrics 실험에서는 사진을 448×364 RGB로 변환하고 DINOv2-S/14를 **재학습하지 않고** 특징 추출기로 사용했다.
- 기준 생산 구간의 초기 512장은 라벨을 사용하지 않고 다뤘다. 외관 특징으로 나눈 4개 그룹에서 덜 이례적인 사진 60%를 선별해 기준 패치 뱅크를 만들었다. 새 이미지의 패치마다 기준 뱅크에서 가까운 3개 특징과의 코사인 거리를 계산한다. 패치 점수는 히트맵이 되고, 상위 1% 패치 점수의 평균은 이미지 점수가 된다. 기준 사진 선별은 전체 초기 사진을 쓰는 대안과 같은 크기의 패치 뱅크로 비교했다. 결과는 아래와 같이 오경보·검수 성과의 개선과 결함 사진 탐지 감소가 함께 나타났다.
- 이미지 경보 기준은 기준 구간과 겹치지 않는 보정 이미지의 점수 **99.5백분위수**로 고정한다. 새 구간의 미확인 사진이나 실제 정답 라벨로 임계값을 다시 맞추지 않는다. 점수는 정상 기준과의 거리이며 결함 확률은 아니다.

### 공정 외관 변화 감지

- 각 이미지의 전체 특징을 128장 단위 창으로 묶어 기준 구간과의 분포 차이(MMD)를 계산한다. 32장씩 창을 이동하며, 기준 구간에서 얻은 변화 점수의 99백분위수를 경보선으로 쓴다.
- **세 창 연속** 경보선을 넘으면 외관 변화 신호를 확정한다. 이 신호는 사진 한 장의 결함 판정과 독립적이다. 변화의 원인이나 실제 공정 변경 시점을 자동으로 알아내는 기능은 아니다.

### 구간 요약과 제한된 검수

- 구간이 끝나면 처리 장수, 이상 점수 분포·추이, 임계값 초과 건수, 외관 변화 신호와 확인할 사진을 함께 보여준다. 이 화면은 실제 운영에서 알 수 있는 모델 출력만 사용한다. 공개 데이터의 정답 라벨은 검수 전 화면에 노출하지 않는다.
- 사진은 **점수 순위**로 고르되 서로 최소 16프레임 떨어지게 한다. 가까운 프레임에 반복된 한 사건이 검수 요청을 독점하지 않도록 하기 위한 규칙이다.
- 임계값에 가까운 사진을 같은 검수 예산에 섞는 대안도 시험했다. 개발 5개 구간에서 발견한 신규 결함 사건은 기존 규칙 **20/43건**, 근접 사진을 2건 섞은 규칙 **17/43건**이었다. 결함 발견을 위한 검수 순위에는 적용하지 않는다.
- 시연에서는 처음 **2건**을 요청한다. 둘 다 정상으로 확인되면 해당 구간의 추가 요청을 마치고, 결함 또는 판단 보류가 있으면 같은 순위 목록에서 최대 **8건**까지 확인한다. 이 절감 규칙은 공개 데이터 재생으로 확인한 후보이며, 현장 적용 전에는 조기 종료 구간의 정기 표본 검수가 필요하다. 확인 결과는 그 사진의 검수·기록에만 사용하며, 탐지 모델이 즉시 바뀌지는 않는다.
- 아래의 **기준 갱신 검증은 별도의 8건 고정 검수 실험**이다. 2건 우선 검수 시연에서 확인한 사진들이 그대로 새 모델의 학습에 쓰였다는 뜻은 아니다.

### 기준 갱신 후보와 적용 판단

- 새 구간의 라벨 없는 초기 사진에서 덜 이례적인 사진을 고르는 **기준 사진 선별**과, 사람이 정상으로 확인한 패치를 기존 기준의 복사본에 추가하는 **검수 기반 후보**를 별도로 시험했다. 결함 또는 판단 보류 사진은 정상 기준에 넣지 않는다.
- 후보는 후속 구간에서 기존 기준과 같은 조건으로 비교한다. 정상 사진 오경보뿐 아니라 결함 사진 탐지와 새로운 결함 사건 발견이 유지되는지 함께 본다.
- 현재 검수 기반 후보는 오경보는 줄였지만 결함 탐지도 줄였다. 따라서 **고정된 기존 DINOv2 기준을 계속 사용하고 자동 갱신은 보류**한다. 현장 판단을 반영하는 경로는 마련했으나, 판단을 받아 모델 성능이 개선됐다고 주장하는 단계는 아니다.

## 4. 실험 설계와 확인된 결과

TSFabrics의 한 생산 시나리오를 기준 구간으로 쓰고, 5개 시나리오에서 방법을 정한 뒤 나머지 16개 시나리오를 같은 규칙으로 평가했다. 각 대상 시나리오는 초기 256장과 64장 간격을 둔 뒤 최대 4,096장까지만 사용했다. 검수할 사진과 변화 신호는 라벨 없이 선정했다. 공개 데이터의 정답은 **선정 후 성능 평가**에 사용했고, 순차 검수 실험에서는 실제 사람의 판단 대신 **요청된 사진의 공개 라벨만** 검수 결과로 재생했다. 외관 변화 시험은 서로 다른 실제 녹화 구간을 알려진 경계에서 이어 붙인 것으로, 결함 사진을 합성한 시험은 아니다.

| 개선 요소 | 같은 조건의 비교 | 결과와 해석 |
| --- | --- | --- |
| 전체 방법 비교 | TSFabrics 결함 포함 4개 구간, 수작업 특징·초기 사진 전체 기준 → DINOv2 특징·선별된 기준 | 이미지 점수의 구간별 평균 AP **66.4% → 85.4%**. 후자가 앞선 구간은 **4개 중 2개**다. 특징 추출기만 바꾼 단일 요인 비교는 아니며, 기준 사진 선별 효과는 다음 행에서 별도로 비교했다. |
| 기준 사진 선별 | 초기 512장 전체 → 라벨 없이 덜 이례적인 사진 308장 선별. 패치 뱅크 크기는 동일하고, 각 기준은 독립된 원본 구간에서 경보선을 보정 | 최종 16개 구간에서 정상 사진 경보 **19,153/26,088 → 1,449/26,088**, 8건 검수로 찾은 신규 결함 사건 **19/90 → 26/90**. 그러나 경보선에서 잡은 결함 사진은 **851/883 → 313/883**으로 감소했다. 평균 AP는 **70.3% → 85.4%**였지만 선별 기준이 앞선 결함 구간은 **4개 중 1개**다. |
| 외관 변화 신호 | 기준 구간의 연속 영상과 16개 다른 실제 녹화 구간을 이어 붙인 시험 | 새 구간 **16개 중 15개**에서 경보, 동일한 기준 녹화 구간의 후속 **16,518장**에서는 경보 **0건**. 경보는 알려진 연결 경계 이후 중앙값 **96프레임**에 확정됐다. 한 녹화 구간의 긴 후속 영상 결과는 일반적인 오경보율이 아니다. |
| 변화 특징 비교 | 동일 MMD·경보 규칙에서 DINOv2 전체 특징 ↔ 32구간 흑백 밝기 히스토그램 | 밝기 히스토그램은 알려진 구간 전환 **16/16개**, DINOv2는 **15/16개**에서 경보가 났다. 다만 동일한 기준 녹화 구간의 후속 513개 점수 창에서 자체 경보선을 넘은 수는 각각 **336개 ↔ 0개**였다. 한 녹화 구간의 결과이므로 336개를 확정 오경보로 부르지 않는다. 현재는 DINOv2 변화 신호를 유지한다. |
| 검수 사진의 시간 분산 | 동일 DINOv2 점수·구간당 8건, 인접 상위 8건 → 최소 16프레임 간격 | 결함 포함 4개 구간의 평균 신규 결함 사건 발견 비율 **41.8% → 71.1%**. |
| 2건 우선 검수 | 최종 16개 구간, 항상 8건 → 우선 2건 후 필요 시 8건 | **12개 구간은 2건에서 종료, 4개 구간은 8건까지 확대**해 자동 요청이 **128건 → 56건**. 이 데이터에서는 양쪽 모두 신규 결함 사건 **26/90건**을 확인했다. 화면에서는 담당자가 정상 2건 뒤에도 추가 6건을 직접 열 수 있다. 56건은 이 수동 추가를 사용하지 않은 실험 결과다. |
| 검수 정상 패치로 기준 갱신 | 별도 15개 구간의 후속 사진, 고정 기준 → 갱신 후보 | 정상 사진 경보 **1,050/20,273 → 0/20,273**. 그러나 탐지한 결함 사진 **202/642 → 153/642**, 신규 결함 사건 **48/65 → 40/65**로 감소해 **갱신 보류**. |

추가로 수작업 특징 점수를 DINOv2 점수와 섞는 방법도 비교했다. 최종 16개 구간에서 DINOv2 단독 대비 결함 포함 구간의 평균 AP가 **85.4% → 81.2%**, 8건 검수에서 찾은 신규 결함 사건이 **26 → 24건**으로 줄어 점수 결합은 채택하지 않았다. 새 구간의 초기 사진으로 만든 선별 기준 역시 8건 검수 사건 발견은 고정 기준과 같았지만 평균 AP가 더 낮아, 운영 기준으로 교체하지 않았다.

기준 사진 선별의 **19,153 → 1,449**와 **851 → 313**은 각각의 기준 뱅크에 대해 원본 구간에서 따로 보정한 경보선을 적용한 결과다. AP와 8건 검수 성과는 목표 구간의 경보선을 선택하지 않고 비교한 지표다. 선별 기준은 현재 사용 중이지만, 결함 사진 경보가 크게 줄어드는 손실이 있어 현장 품질 기준을 충족하는지 별도로 판단해야 한다. 보고서의 단일 정상 사진 사례나 평균 AP만으로 보편적 우수성을 주장하지 않는다.

초기 MVP는 KolektorSDD의 자체 그룹 분리 시험 64장 중 결함 5/8장에 경보가 났고 정상 7/56장에 오경보가 났으며 이미지 AUROC는 0.879였다. 위 TSFabrics 수치와 직접 비교하지 않는다. 또한 공개 데이터의 16개 평가 구간은 이 프로젝트의 앞선 분석에서도 일부 살펴본 적이 있어, 이를 완전히 새로운 현장 검증으로 부르지 않는다. **결함 유형 자동 분류, 실제 검수 결과를 이용한 탐지 성능 향상, 생산라인 처리 속도·설비 연동은 아직 검증한 기능이 아니다.** 별도 속도 측정에서는 RTX 3090 서버에서 448×364 사진을 ZIP에서 읽어 DINOv2 추론과 패치 비교까지 수행했을 때, 8장 배치의 세 구간 중앙 처리량이 **105.48장/초**, 1장씩 처리한 중앙 지연 시간이 **13.95ms**였다. 이는 서버의 축소 이미지 측정이며 현장 PC·원본 해상도·카메라 입력·설비 연동을 포함한 속도가 아니다. 회의에서 언급된 초당 약 100장 사례의 현장 조건을 충족했다고 판단할 수 없다. 발표 구성에서 제안한 자동 라벨링 초안은 현재 **이상 점수·위치와 검수 후보 제시**까지 구현했으며, 결함 유형 라벨 자동 생성이나 확인 라벨로 재학습하는 순환은 향후 과제다. [속도 측정 프로토콜과 결과](../experiments/unsupervised/THROUGHPUT_RESULTS.md).

## 5. 시연에서 보여주는 것

![SurfaceTrace 1080p recorded-run replay](https://gohyunsu.github.io/surface-trace/media/recorded-run-1080p.gif)

GIF는 실제 TSFabrics 사진과 저장된 모델 결과를 1920×1080으로 재생한다. **동일 사진의 수작업 특징·DINOv2 히트맵 비교 → 외관 변화 신호 → 구간 이상 점수와 검수 후보 → 사진별 확인 → 기준 갱신 보류** 순서다. 첫 화면은 성패가 다른 개발 구간 사진 2장과 최종 평가 구간 사진 1장을 예시로 비교하며, 옆의 AP는 별도의 최종 평가 4개 결함 포함 구간에서 계산했다. 외관 변화 화면은 서로 다른 실제 녹화 구간을 알려진 경계에서 연결하고, 바뀐 구간의 1·32·64·96·192번째 실제 사진과 점수 창을 보여준다. 이 사례의 경보는 96번째 프레임에서 확정되며, 이는 실제 공정 변경 시각을 알아낸 결과가 아니다. 가운데 변화·점수·검수 화면은 한 녹화 구간을 따르고, 마지막 갱신 판단은 **별도의 15개 구간 후속 평가** 결과다. 사이트의 새 파이프라인 화면에서는 검수 규칙의 효과도 별도로 비교할 수 있다.

## 6. 동일고무벨트 측에 우선 받고 싶은 피드백

**① 이 프로토타입이 먼저 도와야 할 업무는 무엇인가요?**

**생산 중 자동 판정 / 교대조·배치별 사후 요약 / 변화 발생 시 AI팀 확인 요청** 중 우선순위가 높은 업무를 골라 주시면 좋겠습니다. 현재 구현은 두 번째와 세 번째에 초점을 맞춥니다. 요약을 실제로 볼 사람도 **생산 관리자 / 품질 담당자 / AI 솔루션팀** 중 누구인지 확인하고 싶습니다. 이는 회의에서 말씀해 주신 기간 요약의 활용처를 구체화하기 위한 질문입니다.

**② 현장에 요청할 확인 건수와 시점은 어느 정도가 적절한가요?**

현재 안은 **상위 2건 먼저 확인 → 결함·판단 보류가 있으면 최대 8건**입니다. 이 방식, **매 구간 고정 건수**, **변화 신호가 있을 때만 요청** 중 실제 업무에 맞는 방식을 알려 주세요. 검수 요청을 받을 담당자와 한 교대조·배치에서 처리할 수 있는 건수의 대략적인 상한도 궁금합니다. 상세한 공정 정보나 내부 사진 없이 답할 수 있는 운영 질문입니다.

**③ 새 기준을 적용할 때 어떤 확인 절차가 필요할까요?**

후보 모델은 **품질 담당자의 정상·불량 확인 / 후속 구간에서 오경보·누락 비교 / 일정 기간 기존 모델과 병행 운영 / 최종 책임자의 승인** 중 무엇을 필수로 거쳐야 할까요? 현재 실험에서는 오경보가 줄어도 결함 누락이 늘어 후보를 보류했습니다. 어느 정도의 누락 위험을 허용할 수 있는지, 승인 주체는 누구인지 알고 싶습니다.

우선은 **업무 우선순위, 검수 부담, 기준 갱신의 승인 조건**을 확인하고자 합니다. AI 솔루션팀에서 답하기 어려운 항목은 현업 부서에 전달 가능한지 알려 주시는 것만으로도 다음 개발 범위를 정하는 데 도움이 됩니다.
